# Ручная проверка на настоящем Chrome и Рутокене

Для этапа 5 ([`ROADMAP.md`](ROADMAP.md)) и для любой проверки новой сборки руками. Что уже проверено автоматически
и что нет — [`STATUS.md`](STATUS.md).

## Что понадобится

- Chrome (версия не ниже `minimum_chrome_version` в `src/manifest.json`). Расширение КриптоПро может стоять рядом:
  на сайте, включённом у нас, страница видит только наше, на остальных — КриптоПро (на стенде проверено и с
  настоящими CSP 5.0.13800 и плагином 2.0.15700 под Linux; на Windows — проверьте, пожалуйста).
- Рутокен ЭЦП 2.0 или 3.0 с ключом ГОСТ Р 34.10-2012 (256 или 512 бит) и сертификатом к нему, записанными как
  объекты PKCS#11 (так их создаёт Рутокен Плагин). Контейнеры КриптоПро на токене расширению не видны — решение в
  `CLAUDE.md`. Если такого ключа нет, его можно сделать через наше расширение — следующий раздел.
- Для сверки полей — машина или профиль с настоящим КриптоПро CSP и КриптоПро ЭЦП Browser plug-in, куда вставлен
  тот же Рутокен с тем же сертификатом в хранилище «Личное».

## Установка

1. Драйверы Рутокен (для Windows — <https://www.rutoken.ru/support/download/windows/>).
2. Рутокен Плагин — <https://www.rutoken.ru/support/download/rutoken-plugin/>.
3. Расширение «Адаптер Рутокен Плагин» из Chrome Web Store —
   <https://chromewebstore.google.com/detail/ohedcglhbbfdgaogjhcclacoccbagkjg>.
4. Наше расширение: распаковать архив `cryptopro-via-rutoken-<версия>.zip` (выпуск на странице Releases
   репозитория, артефакт `cryptopro-via-rutoken` прогона CI или `npm run package`), открыть `chrome://extensions`, включить «Режим разработчика», нажать
   «Загрузить распакованное расширение» и выбрать папку `cryptopro-via-rutoken-<версия>` из архива.

## Ключ и сертификат на токене

Проще всего — через наше расширение на тестовом УЦ КриптоПро (на стенде с fake Рутокеном этот путь проходит
тест `tests/stand/testgost.spec.ts`; на устройстве не проверялся):

1. Подключить **один** Рутокен (при нескольких расширение просит оставить один).
2. Открыть <https://testgost2012.cryptopro.ru/certsrv/certrqma.asp>, включить на нём расширение кнопкой (как в
   пунктах 1–2 чек-листа ниже).
3. В списке CSP — «Rutoken Plugin …» (256 бит) и «Rutoken Plugin … (ГОСТ Р 34.10-2012 512 бит)». Заполнить имя,
   нажать «Выдать >», в окне «Рутокен вместо КриптоПро» ввести PIN — «Создать». Ключ создаётся на Рутокене.
4. УЦ сразу выдаёт сертификат: «Установить этот сертификат», PIN — «Записать». Страница пишет «Новый сертификат
   успешно установлен.»
5. Сертификат УЦ для проверки подписи — ссылка «Установить этот сертификат ЦС» на той же странице выдачи
   (`certnew.cer?ReqID=CACert…`): сохранить файл.

Если в окне PIN после «Создать» ошибка, попробуйте ещё раз с «Ключ подписи» вместо «Ключ подписи и обмена»:
экспортные исполнения Рутокен ЭЦП 3.0 ключ «подпись и обмен» не создают (документация Рутокен Плагина).

Другой путь — демо-сайт Рутокена
<https://ra.rutoken.ru/> («Возможности Рутокен Плагин»): «Создание ключей» с алгоритмом ГОСТ Р 34.10-2012
256 бит, затем «Создать заявку на тестовый сертификат» и «Добавить тестовый сертификат». Разделы названы по тексту
сайта; сам этот путь агент не проходил — устройства у него нет. Для проверки подписи понадобится ещё сертификат
УЦ, который выдал сертификат пользователя (файл `.cer` или `.pem`).

## Чек-лист

Отмечайте, что увидели; где не совпало — снимок экрана и текст.

1. Открыть <https://www.cryptopro.ru/sites/default/files/products/cades/demopage/cades_bes_sample.html>. Сайт ещё
   не включён: страница не находит расширения (на стенде она пишет «Расширение не загружено» и «Плагин:
   ожидание загрузки расширения»).
2. Нажать кнопку расширения «КриптоПро через Рутокен». В окне адрес `https://www.cryptopro.ru` и переключатель
   «Включено на этом сайте». Включить: Chrome спрашивает доступ к сайту — разрешить. Вкладка перезагружается,
   с первого раза (1.3.1), даже если окно кнопки при вопросе Chrome закрылось; окно кнопки снова — галочка стоит.
3. Страница пишет «Расширение загружено», «Плагин загружен», «Криптопровайдер загружен», версии 2.0.15000 и
   5.0.13000, криптопровайдер «Rutoken Plugin …».
4. В списке «Выберите сертификат» — сертификат с токена. Выбрать его: карточка заполнена (владелец, издатель,
   даты, отпечаток, алгоритм, статус).
5. «Подписать». Появляется окно «Рутокен вместо КриптоПро»: сайт `https://www.cryptopro.ru`, «11 байт, присоединённая
   подпись», владелец и издатель сертификата. Ввести неверный PIN — окно просит ещё раз (попытки PIN
   ограничены, одной ошибки достаточно). Ввести верный — «Подпись сформирована успешно:» и подпись ниже.
   **Скопировать подпись в файл** `attached.txt`.
6. Отметить «Отделенная подпись» и «Проверять подписанта», «Подписать», верный PIN. **Скопировать подпись** в
   `detached.txt`.
7. «Подписать» и «Отмена» в окне PIN: страница пишет «Возникла ошибка:» и «… отменено пользователем.
   (0x8010006E)».
8. Страница настроек расширения («Настройки» в окне кнопки): в списке `https://www.cryptopro.ru`.
   «Выключить», перезагрузить демо-страницу — снова как в пункте 1.

Дальше — другие демо-страницы КриптоПро с того же сайта; он уже включён. Адреса ниже начинаются с
`https://www.cryptopro.ru/sites/default/files/products/cades/demopage/`.

9. `cades_bes_file.html` — подпись файла. «Выберите файл» — любой небольшой файл, например `document.txt`;
   выбрать сертификат, «Подписать», PIN — «Подпись сформирована успешно:». **Скопировать подпись** в
   `file-attached.txt`. Отметить «Отделенная подпись», ещё раз — в `file-detached.txt`.
10. `cades_xmldsig_sample.html` — XML-подпись. Документ-пример уже в поле; выбрать сертификат, «Подписать», PIN.
    Ниже — XML с элементом `Signature`. **Скопировать** в `signed.xml`.
11. Сертификаты УЦ: страница настроек расширения, «Сертификаты удостоверяющих центров». На вкладке «Корневые» —
    12 корневых из пакета КриптоПро CSP, все включены. На вкладке «Промежуточные и сторонние корневые» «Добавить из
    файла» и «Добавить» — файл сертификата УЦ, который выдал сертификат на токене (для testgost2012 — сохранённый в
    пункте 5 раздела выше): появляется его карточка, включена, с отметкой «корневой», если он самоподписанный, иначе
    «промежуточный». Для квалифицированного сертификата так добавляется сертификат выдавшего его УЦ
    (промежуточный); корневой Минцифры уже есть на первой вкладке.
12. `verify.html` — проверка подписи, без PIN и без обращения к токену. Вставить `attached.txt` из пункта 5,
    «Проверить подпись»: «Тип подписи: CAdES-BES», «Результат проверки: Подпись проверена успешно», владелец и издатель
    сертификата, «Статус сертификата: Сертификат действителен», «Статус подписи: Подпись проверена успешно».
    Окно PIN не появляется.
13. Там же: отметить «Отделенная подпись», вставить `file-detached.txt`, выбрать тот же файл, «Проверить подпись» —
    успешно. Выбрать другой файл — «Результат проверки:» с ошибкой `(0x80090006)`.
14. В настройках на второй вкладке выключить сертификат УЦ из пункта 11, снова проверить `attached.txt` (сайт перезагружать не
    нужно) — ошибка `(0x800B010A)`: цепочка не доходит до включённого корневого. Включить обратно.
    Сайт видит корневые обеих вкладок как хранилище `Root`, промежуточные — как `CA`.
    Настоящий КриптоПро на тех же подписях отвечает так же, но ещё проверяет отзыв сертификата — мы не
    проверяем (решение в `CLAUDE.md`), поэтому КриптоПро без доступа к списку отзыва откажет `(0x800B010E)`, а мы
    нет.
15. Если стоит расширение КриптоПро с настоящим CSP и плагином: на сайте, выключенном у нас (пункт 8), демо-страница
    работает через КриптоПро, на включённом — только через нас (версия плагина 2.0.15000, провайдер «Rutoken
    Plugin …»).
16. Расширенная проверка валидности (1.2.0). В настройках отметить «Расширенная проверка валидности
    сертификата». На демо-странице выбрать сертификат, выданный testgost2012, если корневого тестового УЦ ещё нет
    на второй вкладке: статус «Не действителен». Включить переключатель внизу страницы («показать больше»), нажать
    «Установить корневой сертификат тестового УЦ». Откроется окно расширения с сайтом и отпечатком. «Отмена» —
    страница пишет «Не удалось установить…» с `0x800704C7`. Ещё раз, «Установить» — «Сертификат установлен.»,
    корневой появился на второй вкладке, заново выбранный сертификат «Действителен». Галочку снять, если на
    сайтах, которые показывают только действительные сертификаты, пропали нужные.
17. Недоверенный корневой при установке (1.3.1). Корневой тестового УЦ убрать со второй вкладки, галочка «Сообщать
    о недоверенном корневом сертификате при установке сертификата» включена (по умолчанию). Выпустить сертификат на
    testgost2012 и нажать «Установить этот сертификат»: после PIN страница пишет красным «Данный ЦС не является
    доверенным», окон нет. Клик по «установите этот сертификат ЦС» — окно «Предупреждение системы безопасности» с
    отпечатком. «Нет» — ничего не меняется. Ещё раз по ссылке, «Да» — сообщение, что корневой установлен, корневой на
    второй вкладке; снова «Установить этот сертификат» — «Новый сертификат успешно установлен.». С выключенной
    галочкой красной строки нет.
18. `webtools.html` — сценарии W1–W15 раздела «Сценарии на webtools.html» ниже.

Прислать: `attached.txt`, `detached.txt`, `file-attached.txt`, `file-detached.txt` с подписанным файлом,
`signed.xml`, сертификат УЦ, файлы и заметки сценариев W5–W8 (список — в конце раздела ниже), заметки по пунктам.

## Сценарии на webtools.html

Страница — <https://www.cryptopro.ru/sites/default/files/products/cades/demopage/webtools.html>, наше расширение на ней
включено. Ожидаемое снято на стенде (fake Рутокен, сборка 1.8.1), хеши посчитаны ещё и независимо; на устройстве
отличаются только имена, номера, отпечатки и даты. Где совпало — галочка, где нет — снимок экрана и текст.
Неверный PIN — не больше одного раза подряд: после нескольких ошибок Рутокен блокирует PIN.

**W1. Загрузка, «Общее».** Открыть страницу. Сразу окно «Рутокен вместо КриптоПро»: «…просит показать ключи на
Рутокене.», «Сайт увидит ключи как контейнеры КриптоПро…» — PIN, «Показать». «Общее»: «Расширение загружено»,
«Плагин загружен», «Криптопровайдер загружен», «Версия расширения» — версия нашего расширения, «Версия плагина:
2.0.15000», «Версия криптопровайдера: 5.0.13000», «Криптопровайдер: Rutoken Plugin <версия>». Красных уведомлений
(колокольчик) нет. Вариант: «Отмена» в этом окне — красное «Действие было отменено пользователем. (0x8010006E)
Ошибка заполнения списка контейнеров», «Контейнеры» — «Контейнеры отсутствуют.», клик по считывателю на
«Считывателях» спрашивает PIN снова.

**W2. Подпись сразу после PIN при загрузке (исправлено в 1.8.1).** Обновить страницу, ввести PIN и тут же —
«Создать подпись», CMS, «Подписать». Второе окно PIN («…просит подписать данные.») приходит, когда расширение
дочитает ключи, подпись создаётся. В 1.8.0 так получалась ошибка «19».

**W3. Хэширование (без токена и PIN).** «Хэшировать данные», раскрыть настройки.
- Кодировка UCS2LE, в поле `Привет, мир!`, «Хэшировать» — столбец UCS2LE таблицы.
- Кодировка BASE64, в поле `Привет, мир!` и кнопка «B64» справа от поля (станет `0J/RgNC40LLQtdGCLCDQvNC40YAh`),
  «Хэшировать» — столбец BASE64 (хеш байтов текста в UTF-8). Без «B64» — «Данные не в Base64. (0x80070057)».
- Формат результата BASE64, ГОСТ 34.11-2012 256, UCS2LE — `xkZ/ywDCoaQRnscx2qPM36w59y0+z9wtDMHkQRm8Zs0=`.

**W4. Подпись CMS и проверка.** «Создать подпись», CMS, CAdES-BES, цепочка «Все», без «Отделенная подпись», в поле
`Привет, мир!`, «Подписать». Окно PIN: «…просит подписать данные.», «21 байт, присоединённая подпись.», сертификат —
PIN, «Подписать»; в поле результата — Base64. Скопировать; «Проверить подпись», тип «Автоматически», вставить в
«Подпись», «Проверить подпись». Ожидаемо: «Тип подписи: CAdES-BES», «Результат проверки: Подпись проверена
успешно»; ниже «Подписанты: 1», владелец, «Статус: Сертификат действителен», «Дата подписи: <время подписи> UTC»,
«Статус подписи: Подпись проверена успешно»; в «Исходные данные» — `Привет, мир!`.
- Если «Тип подписи: Неизвестно», «Cannot find the original signer. (0x8009100E)» — у расширения нет промежуточного
  сертификата вашего УЦ. Цепочку наша проверка строит из подписи (в нашей — только ваш сертификат) и хранилищ
  расширения, из интернета не загружает: добавить сертификат УЦ, выдавшего ваш (файл с сайта УЦ), на вторую вкладку
  настроек расширения и проверить снова. Все отказы на этой странице выглядят так: после первой ошибки она повторяет
  проверку по-другому и показывает ошибку повтора (с плагином КриптоПро — так же).
- Отсоединённая: отметить «Отделенная подпись», подписать (в окне PIN — «отсоединённая подпись»). Проверка — с той же
  галочкой на вкладке проверки и `Привет, мир!` в «Исходные данные»: «Подпись проверена успешно»; с `Привет, мир?`
  или пустым полем — «Cannot find the original signer. (0x8009100E)».
- Тип «PKCS7» на вкладке проверки — «Тип подписи: PKCS7», «Подпись проверена успешно».
- Цепочка «Все», «Без корневого», «Конечный» — в подписи только ваш сертификат: цепочку Рутокен Плагин не кладёт.
  «Нет» — подпись без сертификата, наша проверка её не проверит (0x8009100E): сертификат подписанта она ищет только
  в подписи и хранилищах расширения (КриптоПро нашёл бы его в своём хранилище).
- CAdES-XLT1 и CAdES-A — «Тип подписи 93 (221) пока не поддерживается: доступны CAdES-BES, CAdES-T и PKCS#7
  (0x80004001)», окна PIN нет.
- «Отмена» в окне PIN — «Попытка подписать CMS: Действие было отменено пользователем. (0x8010006E)». Неверный PIN
  один раз — в окне «Неверный PIN-код. Попробуйте ещё раз.», окно остаётся.
- Сохранить присоединённую и отсоединённую подписи (`attached.txt`, `detached.txt`); есть машина с КриптоПро —
  проверить их там.

**W5. CAdES-T.** CMS, тип CAdES-T, в поле TSA — `http://testca2012.cryptopro.ru/tsp/tsp.srf` (тестовая служба
КриптоПро) или служба своего УЦ. В окне PIN — «присоединённая подпись со штампом времени», «Служба штампов
времени: testca2012.cryptopro.ru»; подпись создаётся, сохранить в `cades-t.txt`. Наша проверка (если цепочка строится, W4): «Тип
подписи: CAdES-BES», «Подпись проверена успешно» — штамп мы не проверяем, и страница после отказа для CAdES-T проверяет
подпись как CAdES-BES; есть машина с КриптоПро — проверить `cades-t.txt` там (тип CAdES-T). Пустое поле TSA — «The URL
of TSP service is not specified (0xC2100121)»; адрес `https://…` — «Рутокен Плагин обращается к службе штампов
времени только по HTTP: … (0x80070057)».

**W6. XML: XMLDSig, XAdES-BES, XAdES-T.** «Создать подпись», XML, в поле `<document><title>Договор</title></document>`.
- XAdES-BES (по умолчанию), ENVELOPED: окно PIN «XML-подпись XAdES-BES вложенная, 43 символов.»; результат — XML с
  подписью и `xades:QualifyingProperties`. ENVELOPING — «оборачивающая»; тип XMLDSig — подпись без `xades`.
- Проверка каждой: «Тип подписи: XML», «Подпись проверена успешно», «Дата подписи: -». В подписанном XML заменить
  `Договор` на `Догавор` — «Попытка проверить XML: Invalid Signature. (0x80090006)».
- TEMPLATE, когда в документе нет шаблона подписи, — «В документе нет подписи для заполнения (0x80092004)».
- XAdES-T, поле TSA — как в W5 (годится и `https://`). Первый раз — окно расширения «Доступ к службе штампов
  времени» с сайтом и службой, «Разрешить», затем вопрос Chrome о доступе к сайту службы — разрешить; окно PIN
  называет службу; в подписи — `xades:EncapsulatedTimeStamp`. Второй раз окон доступа нет. «Отмена» в окне
  расширения — «Пользователь не разрешил обращаться к службе штампов времени. (0x800704C7)», PIN не спрашивается.
- XAdES-XLT1 — «Подпись XAdES-X Long Type 1 не поддерживается расширением: доступны XAdES-BES и XAdES-T
  (0x80004001)».
- Сохранить `xades-bes.xml` и `xades-t.xml`. Есть машина с КриптоПро — проверить обе там, записать ответ, и сделать
  там XAdES-BES своим сертификатом (`cryptopro-xades.xml`): по ней сверю устройство подписи КриптоПро с нашим.

**W7. Шифрование CMS.** «Зашифровать данные», получатель — свой сертификат, тип CMS. Для 28147-89, MAGMA,
MAGMA_OMAC, KUZNYECHIK, KUZNYECHIK_OMAC: текст длиннее 5 КБ, «Зашифровать» — окно PIN «…просит зашифровать данные.»
(Рутокен Плагин шифрует только после входа), результат Base64; «Расшифровать данные», вставить, «Расшифровать» —
окно PIN «…просит расшифровать данные», затем тот же текст. ГОСТ 28147-89 на стенде расшифровать не удаётся (fake
Рутокен), здесь — первая проверка. Сохранить по одному сообщению каждого алгоритма в `encrypted-<алгоритм>.p7e`.
Есть машина с КриптоПро CSP и его плагином (наше расширение на этом сайте там выключено): на её `webtools.html`
поставить файл своего сертификата («Сертификаты», «Установить сертификаты» — он попадёт в «Другие
пользователи»), зашифровать для него текст длиннее 5 КБ алгоритмами 28147-89, KUZNYECHIK и MAGMA, сохранить и
расшифровать у нас («Расшифровать данные», «Выбрать файл»).

**W8. Шифрование XML.** Тип XML, 28147-89, получатель — свой сертификат: окна PIN нет, результат — XML с
`EncryptedData`. «Расшифровать данные» его же — окно PIN, затем исходный документ: первая проверка выработки ключа
(`derive`) на настоящем Рутокене (на стенде fake Рутокен отвечает ошибкой 147). Сообщения агента своему сертификату
(`xml-1`…`xml-4`, в каждом свой режим или набор параметров): нашим расширением — `xml-1` и `xml-2`; КриптоПро (наше
расширение на этом сайте выключено) — все четыре, записать, какие открылись. КриптоПро зашифровать XML своему
сертификату (тип XML, 28147-89), сохранить в `cryptopro-xml.xml` и расшифровать нашим расширением.

**W9. Сертификаты.** «Текущий пользователь»: «Личное» — сертификаты с Рутокена; «Доверенные корневые центры
сертификации» — включённые сертификаты первой вкладки настроек расширения; «Промежуточные центры сертификации» —
второй вкладки; «Другие пользователи» и «Запросы заявок на сертификат» — «Сертификаты отсутствуют.». «Компьютер» —
то же, что «Текущий пользователь»; «Контейнер» — сертификаты с Рутокена.
- Свой сертификат: «Криптопровайдер: Rutoken Plugin …», «Ссылка на закрытый ключ:
  `\\.\Rutoken <номер токена>\<id сертификата>`», срок ключа, «Статус: Действителен», «Установлен в хранилище: Да». «Цепочка
  сертификата» — «Для вывода цепочки сертификата требуется версия плагина 2.0.15000 или выше»; с «Расширенной
  проверкой валидности» в настройках расширения — цепочка от корневого до вашего (если промежуточный есть на второй
  вкладке).
- «Экспортировать сертификат» — файл `CN=<имя>.cer` (Base64), отпечаток тот же.
- «Удалить сертификат» — вопрос страницы, «OK» — красное «oStore.Remove is not a function»: ничего не удаляется
  (сертификат удаляется с Рутокена вместе с ключом — «Удалить контейнер», W12).
- «Установить сертификаты» из файла: свой сертификат — окно PIN «…просит записать сертификат на Рутокен.», затем
  «Сертификат Установлен, Хранилище: My», второй копии на токене нет (в «Личное» столько же сертификатов);
  сертификат, ключа которого на токене нет, — окно PIN, затем «Добавление в хранилище addressbook не поддерживается
  расширением (0x80004001)»; корневой — окно расширения «Предупреждение системы безопасности» («Нет» —
  «Пользователь не разрешил добавить сертификат. (0x800704C7)»).
- «Импортировать ключи» — выбор файла, затем «Для импорта PFX требуется версия плагина 2.0.15260 или выше»: ключи
  из PFX на Рутокен не импортируются.

**W10. Списки отзыва.** «Работа с CRL недоступна в данной версии плагина.» — так и должно быть: списков отзыва у
расширения нет (отзыв не проверяется, решение владельца).

**W11. Считыватели.** Рутокен — строка «имя считывателя/метка токена/модель и номер», флаги «CARRIER_FLAG_REMOVABLE»
и «CARRIER_FLAG_UNIQUE», контейнеры — ключи токена `\\.\Aktiv Rutoken ECP 0\ID_…`, без нового PIN. Только
устройство: вынуть токен и вставить обратно — через пару секунд уведомления «Извлечен носитель» и «Вставлен
носитель». «Установить сертификаты со считывателя» — окно PIN «…просит записать сертификат на Рутокен.», затем
«Сертификат из контейнера установлен»: сертификат уже на токене, второй раз не пишется.

**W12. Контейнеры.** Ключи токена с именами `\\.\Aktiv Rutoken ECP 0\ID_…` — те же, что показывал КриптоПро
(кроме его собственных контейнеров); у выбранного — ключ, его алгоритм, сертификат, «Ключей: 1». «Установить
сертификат» — как в W11. «Импортировать ключи» — как в W9. «Удалить контейнер» удаляет ключ и его сертификат
безвозвратно — только на ненужном ключе (например, выпущенном на testgost2012).

**W13. Основные сертификаты.** Встроенные корневые расширения — «Установлен». «Установить» у промежуточного
(например, «Минцифры России НУЦ подчиненный») — сразу «Сертификат Установлен, Хранилище: CA», он появляется на
второй вкладке настроек расширения; у корневого — окно расширения «Предупреждение системы безопасности», «Да» —
«Хранилище: Root».

**W14. Логирование, «Настройка плагина».** «Включить логирование» — в журнале сообщения адаптера Рутокен Плагина
(`"rutoken":{…}`). «Настройка плагина» — красное «Ошибка при открытии страницы "Настройка доверенных сайтов": не
поддерживается в Safari»: это окно КриптоПро, у нас сайт включается кнопкой расширения.

**W15. Повторно после перезагрузки страницы.** Подпись и шифрование после обновления страницы (F5) — снова окно PIN
при загрузке (W1) и всё работает; с двумя вкладками webtools.html одновременно — записать, что вышло (на стенде не
проверялось).

Прислать: подписи из W4 и `cades-t.txt` из W5, `xades-bes.xml`, `xades-t.xml` и `cryptopro-xades.xml` из W6,
`encrypted-*.p7e` и сообщения КриптоПро из W7, `cryptopro-xml.xml` и какие сообщения открылись из W8, номера
сценариев, где не совпало, со снимками.

## Сверка полей с КриптоПро

1. На машине с настоящим КриптоПро открыть демо-страницу (наше расширение на этом сайте выключено или не
   установлено), дождаться «Плагин загружен».
2. Открыть DevTools (F12), вкладку Console. Chrome может попросить сначала ввести `allow pasting`.
3. Вставить весь текст [`tools/dump-fields.js`](../tools/dump-fields.js) и нажать Enter. Результат — JSON — уже
   скопирован в буфер обмена; сохранить в `cryptopro.json`. Скрипт ничего не подписывает и PIN не спрашивает.
4. То же самое в Chrome с нашим расширением, включённым на демо-странице; сохранить в `ours.json`.
5. Сравнение: `node scripts/compare-fields.ts cryptopro.json ours.json` — печатает каждое различие. Или просто
   прислать оба файла.

В обоих файлах есть `userAgent`, серийный номер и отпечаток сертификата и поля его субъекта — это данные
сертификата; если они не для чужих глаз, пришлите только результат сравнения.
