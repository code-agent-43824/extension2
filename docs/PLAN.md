# PLAN — этап 1: тестовый стенд без железа

Цель этапа — из [`ROADMAP.md`](ROADMAP.md): автотест в Chromium, в котором страница-пробник через **настоящий**
Адаптер Рутокен Плагин и **настоящий** Рутокен Плагин находит fake Рутокен, читает его сертификат и подписывает.
Устройство стенда — раздел 8 [`ANALYSIS.md`](ANALYSIS.md).

Обозначения: `[ ]` не начато, `[~]` в работе, `[x]` сделано, `[!]` не получилось (причина в `JOURNAL.md`).

## Действия

- [~] **1. Каркас Node-проекта.** `package.json`, TypeScript, esbuild, Vitest, Playwright (Chromium из
  `/opt/pw-browsers`, без скачивания), `.gitignore` для `vendor/` и сборки. Команды сборки и тестов — в `CLAUDE.md`.
- [ ] **2. Получение вендорских файлов.** Скрипт скачивает в `vendor/` (вне git) и проверяет по SHA-256:
  Рутокен Плагин 4.12.3 deb для amd64, CRX Адаптера Рутокен Плагин, портируемый fake Рутокен и тест-кит
  SoftHSMv2 `v2.7.0-portable.42` для linux-x64. Хеши хранятся в одном файле рядом со скриптом; несовпадение —
  громкая ошибка, а не молчаливое обновление.
- [ ] **3. Сборка стенда.** Скрипт раскладывает Рутокен Плагин в каталог стенда без установки в систему, подменяет
  `librtpkcs11ecp.so` на `libsofthsm2.so`, включает `FAKE_RUTOKEN_ECP = true`, пишет манифест native host в профиль
  Chromium с путём к `FireWyrmNativeMessageHost`, распаковывает адаптер и вписывает в его манифест открытый ключ из
  заголовка CRX, чтобы id совпал с `allowed_origins`.
- [ ] **4. Токен с ключом и сертификатом.** Инициализация токена, ключ ГОСТ Р 34.10-2012/256 и сертификат на нём.
  По умолчанию: ключ генерирует сам Рутокен Плагин (`generateKeyPair`), сертификат выпускает тестовый УЦ скрипта
  стенда, сертификат импортируется `importCertificate`. Если свой УЦ окажется дорогим — выбрать другой способ и
  записать в `JOURNAL.md`.
- [ ] **5. Дымовой тест стенда.** Playwright поднимает Chromium с адаптером, открывает локальную страницу-пробник:
  `rutoken.ready` → `loadPlugin` → `enumerateDevices` → `enumerateCertificates` → `login` → `sign` → `verify`.
  Тест зелёный локально.
- [ ] **6. CI.** GitHub Actions: сборка стенда и дымовой тест на каждый push в `main`.

## Проверки, которые этап должен закрыть

Гипотезы, от которых зависит стенд; результат каждой — в `JOURNAL.md`:

- FireWyrmNativeMessageHost грузит `librtpkcs11ecp.so` из своего каталога (а не из системного пути).
- Хосту и плагину достаточно `libpcsclite`, а `pcscd` без USB-считывателей не мешает.
- Chromium в Playwright загружает распакованный адаптер с нужным id и пускает его к native host в headless-режиме.
