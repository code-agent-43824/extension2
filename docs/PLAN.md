# PLAN — этап 5: проверка владельцем на живом Рутокене

Начат 2026-09-23 после проверки этапа 4 владельцем.

Цель этапа — из [`ROADMAP.md`](ROADMAP.md): владелец ставит расширение в настоящий Chrome с настоящим Рутокеном и
проходит демо-страницу КриптоПро по чек-листу. До этого, по решению владельца от 2026-09-23, расширение
включается только на выбранных сайтах: без этого любой сайт может вызвать подпись, а настоящий КриптоПро
перехватывается везде (риски 7 и 9 в [`ANALYSIS.md`](ANALYSIS.md)).

Обозначения: `[ ]` не начато, `[~]` в работе, `[x]` сделано, `[!]` не получилось (причина в `JOURNAL.md`).

## Действия

- [x] **1. Включение по сайтам.** Статического content script больше нет. Список включённых сайтов хранится в
  `chrome.storage.local`; фоновый скрипт регистрирует `page.js` (`chrome.scripting.registerContentScripts`, мир
  `MAIN`, `document_start`) только для них. Доступ к сайту — необязательное разрешение (`optional_host_permissions`):
  Chrome спрашивает его, когда пользователь включает сайт, и при установке расширению не нужен доступ ко всем
  сайтам. Отозвал доступ в настройках Chrome — сайт выключается.
- [x] **2. Окно на кнопке расширения и страница настроек.** На кнопке: адрес текущего сайта и переключатель
  «Включено на этом сайте», после переключения вкладка перезагружается. В настройках: список включённых сайтов с
  кнопкой «Выключить» и поле для добавления адреса.
- [x] **3. Тесты.** Модульные — на логику списка и регистрации с поддельным `chrome`. На стенде: сайт не включён —
  страница работает без нас; включён через настройки — демо-страница подписывает; выключен — снова без нас.
  Существующие тесты демо-страницы сначала включают сайт. Окно кнопки на стенде открывается во вкладке: открыть
  настоящее всплывающее окно тест не может (`JOURNAL.md`).
- [x] **4. Сборка для владельца.** Архив `dist/cryptopro-via-rutoken-<версия>.zip` из `npm run package`; CI
  выкладывает его артефактом `cryptopro-via-rutoken` каждого прогона.
- [x] **5. Инструкция и чек-лист.** Что поставить (Рутокен Плагин, Адаптер из Chrome Web Store, наше расширение),
  как подготовить на Рутокене ключ ГОСТ и сертификат в PKCS#11, что пройти на демо-странице и что прислать —
  [`MANUAL-CHECK.md`](MANUAL-CHECK.md).
- [x] **6. Сверка полей с КриптоПро.** Вместо отдельной страницы — `tools/dump-fields.js`: его вставляют в консоль

- [x] **8. Эксперимент владельца: сертификат с тестового УЦ КриптоПро.** Поручение владельца 2026-09-23: на

  установить его на токен, затем подписать им на демо-странице и проверить подпись. Для этого эмулируются объекты

## Значения по умолчанию, выбранные агентом

- **Что считается сайтом.** Origin: схема, хост и порт (`https://example.ru`); только `http` и `https`.
  Поддомены включаются отдельно.
- **Где правда о списке.** В `chrome.storage.local`; разрешение на доступ — условие, а не сам список. Так тест на
  стенде может выдать разрешение заранее, а включение и выключение пройдут через тот же код, что у пользователя.
- **Какие «криптопровайдеры» видит страница запроса** (действие 8). Два: тип 80 (ГОСТ Р 34.10-2012 256 бит) и
  тип 81 (512 бит, к имени добавлено «(ГОСТ Р 34.10-2012 512 бит)»), оба с именем из `About.CSPName`, как у
  сертификатов с токена. Ключ создаётся под выбранный тип; «ключ подписи» — `KEY_SPEC_SIGN`, иначе
  `KEY_SPEC_SIGN_AND_EXCHANGE`. Флаг «экспортируемый ключ» не выполняется: ключ Рутокена не экспортируется. Уже
  существующий ключ и хранилище компьютера отклоняются с понятной ошибкой.
- **На какой токен.** На единственный подключённый: сайт токен не называет, а угадывать при нескольких — значит
  рисковать записать не туда. При нескольких — ошибка «оставьте один».
- **Что ставит `InstallResponse`.** Только сертификат пользователя, после проверки, что на токене есть его ключ
  (иначе сертификат снимается и ошибка `0x80092004`, которую страница УЦ понимает). Сертификаты УЦ из ответа не
  пишутся: для подписи они не нужны, а хранилища корневых у нас нет. Повторная установка того же ответа — не ошибка.
- **Хранилище корневых** (действие 12). Лежит в `chrome.storage.local`; при первом открытии заполняется
  встроенными сертификатами, все включены, хранилище включено. Удалённый встроенный сертификат возвращается только
  добавлением из файла. Промежуточные сертификаты пакета (`tmpcerts/ca`) не берутся: это хранилище корневых.
  Добавить можно любой сертификат X.509; файл — DER, PEM (один или несколько сертификатов) или base64 без
  заголовков, как сохраняет КриптоПро; повтор по отпечатку SHA-1 не добавляется.
- **Фреймы.** Скрипт внедряется и во фреймы включённого сайта (`allFrames`), но только если адрес самого фрейма
  тоже включён.
