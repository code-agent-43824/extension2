## Что работает

- Тестовый стенд без железа (`npm run stand`): настоящий Рутокен Плагин 4.12.3.0 и Адаптер 1.1.0.0 в headless
  Chromium, fake Рутокен SoftHSMv2 `v2.7.0-portable.42`, ключ ГОСТ 2012/256 и сертификат тестового УЦ на токене.
- Дымовой тест стенда (`npm run test:stand`): подпись CAdES-BES присоединённая и отсоединённая, проверка с
  цепочкой. Зелёный локально и в CI (GitHub Actions `ci`, прогоны 2026-09-23, стенд собирается на чистом
  раннере с нуля).

  «Криптопровайдер загружен», список сертификатов с токена и карточку выбранного сертификата

- Включение по сайтам: по умолчанию расширение не трогает ни один сайт; сайт включается переключателем на кнопке
  расширения или на странице настроек, Chrome при этом спрашивает доступ к сайту. На стенде проверено, что
  невключённый и выключенный сайт работает без нас (`tests/stand/sites.spec.ts`); окно на кнопке проверено во
  вкладке, настоящее всплывающее окно — только вручную.
- Сборка для ручной установки (`npm run package`, артефакт CI) и инструкция с чек-листом —
  [`MANUAL-CHECK.md`](MANUAL-CHECK.md). На настоящем Chrome с настоящим Рутокеном ещё не проверялось.
- Подпись на демо-странице: окно с сайтом, сертификатом и PIN, затем CAdES-BES присоединённая и отсоединённая,

## Известные проблемы

- Форматы `SubjectName`, `IssuerName`, дат и отпечатка не сверены с настоящим КриптоПро (`JOURNAL.md`, этап 3).
- `HasPrivateKey()` всегда `true` для сертификатов пользователя, `IsValid()` и `CheckCertificate` проверяют только
  сроки.
- Выпуск сертификата: сертификаты УЦ из ответа не ставятся; «понятное имя» сертификата не сохраняется; ключ
  «подпись и обмен» (выбор страницы по умолчанию) экспортные Рутокен ЭЦП 3.0 не создают — тогда нужен «ключ
  подписи»; эмулированы только объекты, которые вызывает certsrv.
- Вход ИП — на lkipgost2.nalog.ru, только по ГОСТ TLS, из Chrome недоступен.
- Нет `Certificate.ExtendedKeyUsage` и `CoSignCades`: сайты действия 14 вызывают их для документов, не для входа.
- Проверка подписи: отзыв сертификатов не проверяется (решение владельца 2026-09-24; КриптоПро без списка отзыва
  отказывает `0x800B010E`); промежуточные УЦ берутся только из самой подписи; CAdES-T и X Long не проверяются
  (`0x80004001`), подписи RSA тоже; `GetMsgType` называет подписи X Long и A типом CAdES-T (не сверено); у подписанта нет `AuthenticatedAttributes2`; `Certificate.IsValid()` цепочку
  по-прежнему не строит.
- `SignedXML`: Base64 в `Content` — только документы в UTF-8; преобразования — только enveloped-signature и C14N;
  ссылки `#id` находят кроме `xml:id` ещё `Id`/`ID`/`id` (настоящий плагин — только `xml:id`).
- `HashedData`: HMAC-алгоритмы не поддерживаются.
- В подпись не попадают атрибуты сайта (время подписи ставит Рутокен Плагин, «имя документа» теряется) и цепочка
  сертификатов; CAdES-T и X Long не поддерживаются (этап 6).
