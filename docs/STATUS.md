## Известные проблемы

- Форматы `SubjectName`, `IssuerName`, дат и отпечатка не сверены с настоящим КриптоПро (`JOURNAL.md`, этап 3).
- `HasPrivateKey()` всегда `true` для сертификатов пользователя. `IsValid()` без галочки расширенной проверки
  смотрит только сроки. С галочкой цепочка без издателя в наших хранилищах — один сертификат без причины:
  промежуточные и корневые по ссылкам из сертификата (AIA) не скачиваются. `CheckCertificate` проверяет только сроки.
- Выпуск сертификата: сертификаты УЦ из ответа ставятся только после «Да» на вопрос о корневом (галочка
  включена), без корневого в ответе — не ставятся; «понятное имя» сертификата не сохраняется; ключ
  «подпись и обмен» (выбор страницы по умолчанию) экспортные Рутокен ЭЦП 3.0 не создают — тогда нужен «ключ
  подписи»; эмулированы только объекты, которые вызывает certsrv.
- Вход ИП — на lkipgost2.nalog.ru, только по ГОСТ TLS, из Chrome недоступен.
- Нет `Certificate.ExtendedKeyUsage` и `CoSignCades`: сайты действия 14 вызывают их для документов, не для входа.
- Проверка подписи: отзыв сертификатов не проверяется (решение владельца 2026-09-24; КриптоПро без списка отзыва
  отказывает `0x800B010E`); промежуточные УЦ — из самой подписи и из второй вкладки хранилища, из интернета (AIA) не загружаются; CAdES-T и X Long не проверяются
  (`0x80004001`), подписи RSA тоже; `GetMsgType` называет подписи X Long и A типом CAdES-T (не сверено); у подписанта нет `AuthenticatedAttributes2`.
- `SignedXML`: Base64 в `Content` — только документы в UTF-8; преобразования — только enveloped-signature и C14N;
  ссылки `#id` находят кроме `xml:id` ещё `Id`/`ID`/`id` (настоящий плагин — только `xml:id`).
- `HashedData`: HMAC-алгоритмы не поддерживаются.
- Шифрование (`JOURNAL.md`, 2026-10-08): Рутокен Плагин шифрует только после ввода PIN; расшифрование ГОСТ
  28147-89 на стенде не проверено (fake Рутокен отвечает ошибкой 147); сообщения «Магмой» длиннее 1 КБ и
  «Кузнечиком» длиннее 4 КБ OpenSSL с GOST-движком 3.0.2 расшифровывает иначе, чем Рутокен (разный размер секции
  CTR-ACPKM), как поступает КриптоПро — не проверено; на webtools.html получателем можно выбрать только сертификат с
  токена (хранилище «Другие пользователи» у нас пустое).
- XML-шифрование: формат взят из КриптоПро .NET и форума КриптоПро, сам плагин КриптоПро не сверен (режим CBC без
  преобразования ключа, набор параметров Z); только ГОСТ 28147-89 и ключи ГОСТ Р 34.10-2012; `derive` на настоящем
  Рутокене не проверен; расшифровываются только `EncryptedKey` с сертификатом получателя (`X509Certificate`), все
  `EncryptedData` документа — для сертификатов одного токена.
- Считыватели: `Name`, `NickName` и `Media` не сверены с КриптоПро. Контейнеры — только ключи, которые видит Рутокен
  Плагин: контейнеров формата КриптоПро на Рутокене нет; `UniqueName` (равен `FQCN`) и `Media` не сверены;
  webtools.html перечисляет контейнеры сразу при открытии, поэтому PIN спрашивается при загрузке страницы.
- XAdES: образца плагина КриптоПро нет, устройство подписи с ним не сверено (`SigningCertificate`, а не V2; имена
  `Id`; штамп XAdES-T в подписи по шаблону КриптоПро, по сообщению с форума, не ставит, мы ставим). Шаблон со своими
  `QualifyingProperties` заполняется как есть, XAdES-T добавляет в них штамп. Штамп при подписи проверяется только на
  оттиск и nonce, подпись службы — нет (как у CAdES-T); `Verify` штамп XAdES-T не проверяет. Подтверждённые службы
  штампов в настройках расширения не показаны; доступ к ним забирается в настройках Chrome (тогда расширение спросит
  снова). XAdES-X Long Type 1 и XAdES-A — понятный отказ.
- webtools.html (обход 2026-10-08, `JOURNAL.md`): любой отказ проверки CMS страница показывает как `0x8009100E`,
  CAdES-T — как успешную проверку CAdES-BES; подпись без сертификата (цепочка «Нет») наша проверка не проверяет;
  «Удалить сертификат» — `oStore.Remove is not a function`; чужой сертификат из файла спрашивает PIN и на миг пишется
  на токен. Очередь операций с токеном — в пределах страницы, не между вкладками.
- В подпись не попадают атрибуты сайта (время подписи ставит Рутокен Плагин, «имя документа» теряется) и цепочка
  сертификатов; CAdES-X Long и CAdES-A не поддерживаются (этап 6). CAdES-T: штамп при подписи не проверяется (решение
  владельца 2026-10-08), служба штампов — только по HTTP (так умеет Рутокен Плагин).
